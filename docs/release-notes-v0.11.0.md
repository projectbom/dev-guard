# DevGuard v0.11.0

`@dev-guard/cli` 0.11.0 and `@dev-guard/core` 0.11.0. All changes are in the CLI; core is version-aligned (no code changes) so the two install together as before.

## Highlights

- **Faster `prepare_task_context`.** The working-tree content hash now seeds its temporary Git index from the real index (Git's stat cache) instead of `read-tree HEAD`, so it re-hashes only changed files; it is computed once per call instead of twice; and ranking no longer rebuilds per-index data for every scored file. Median on synthetic repositories: 10K files ~1.66s → ~0.37s, 25K files ~3.1s → ~0.58s. No cross-call cache: task, Git and validation state are re-read on every call.
- **Routing outside the deep Code Index.** The deep index stays bounded (~1,200 representative files with content, symbols and tokens). `prepare_task_context` now also ranks every project path by filename/path terms (rare terms weigh more; common and numbered names never match loosely), reads only the best few files outside the deep index for that call, and lets the normal ranking assign TARGET/CANDIDATE. Nothing is written to the index. On synthetic 5K/10K/25K repositories, out-of-index task targets with a filename or path signal went from 0 found to found (3/4, 3/4, 4/5 in the final run); a target with no path signal at all still needs a targeted search.
- **Project Knowledge on large repositories.** UI pages, Next.js API routes (app `route.ts` + `pages/api`) and HTTP-framework handlers (Express, Fastify, Koa, Hono, …) have separate bounded budgets, so API routes no longer crowd pages out (5K+ synthetic repositories: 0 → 200 pages). Samples are representative — shallow routes first, spread across workspaces and route sections. Handlers are found in two stages (framework dependency and route-shaped paths first, then bounded content reads that expand into directories where routes were found): 10K synthetic, 36 → all 800 handlers detected, 600 kept as 300 route entries with methods merged. A new `coverage` field records found vs kept per category.
- **Compact dashboard.** The first screen answers five questions — Health (setup/watch only), Thread (Room to continue / Next large task: new thread / New thread recommended), the current task in one line, the single biggest context problem, and one next action — then at most five task numbers (Context — provider-observed only, Read plan, Suggestions used, Validation, Files changed), one estimated context-flow chart (`~43K`, never fake precision), and collapsed Details (read plan, execution lineage, search, validation evidence, timeline, other issues, reports, setup, project, raw telemetry). One `/api/overview` poll replaces the separate state/efficiency polls; page ~104 KB → ~75 KB. Korean copy is short product language.
- **`.devguard/` stays out of Git automatically.** In a Git repository, the first `watch` (or `setup`) appends `.devguard/` and `devguard.backup-*/` to `.gitignore` (creating it if needed) unless Git already ignores them — existing lines are never changed, reordered or duplicated, CRLF files stay CRLF. `AGENTS.md`, `CLAUDE.md`, `.mcp.json` and `.codex/config.toml` are not ignored. If `.devguard/` is already tracked, DevGuard warns and never touches the Git index (`git rm -r --cached .devguard` is yours to run). Outside Git nothing is written. `setup --dry-run` reports what it would do.

## Notes

- Benchmarks are synthetic monorepos generated for this release (1K–25K files); real repositories differ. Not every file is deeply indexed, and recall without any path or filename signal is not claimed.
- No new dependencies, no native code, no AI in the default path. CLI tarball ~511 KB → ~519 KB.
- Knowledge written by 0.10.x stays valid; `coverage` appears after its next structural refresh.
